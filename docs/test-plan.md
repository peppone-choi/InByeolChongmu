# 검증·평가 계획

상태: 로컬 백엔드와 자료 도구의 자동 검증을 구현했습니다. Node 표준 테스트와 Python 자료 회귀 검증이 있으며 Flue·OpenAI·Jev의 소량 연결 검사도 제공하며 전체 모델 품질 평가·제품 전체 인수는 후속입니다.

## 검증 단계

1. **자료 검증**: JSON 파싱, ID 고유성, SKU·주문 참조, 주문 금액, 사례 기대값, Markdown 링크를 확인합니다. 제품 동작 검증과 구분합니다.
2. **코드 단위 검증**: 추출값 스키마·연락처 형식·할인 경계·금액·수량·마감·근거 불일치 처리. 샘플 가격 규칙과 실제 정책을 혼용하지 않습니다.
3. **서비스 통합 검증**: 주문 저장·승인·상태 전이, 트랜잭션 실패 롤백, 재시도·중복 명령·동시 차감, 외부 의존 장애를 검증합니다.
4. **화면 E2E 검증**: UC-01~06을 브라우저에서 수행하고 원문·결과·상태·내보내기 파일·발송 정정을 확인합니다. 가상 자료만 사용하고 검증 후 이번 실행 데이터만 정리합니다.
5. **모델 품질·실사용 평가**: 가상 회귀 사례와 실제 비식별 평가를 분리합니다. 기능 통과만으로 실제 시간 절감 효과를 주장하지 않습니다.

## 자료와 인수조건 추적

[DM 40건](samples/dm-cases.json)의 `expected`는 필수 검증 항목입니다. `DM-002`만 [완전한 출력 예시](samples/analysis-example.json)가 있으며 나머지는 고정 문자열 정답이 아닙니다. `must_not_claim` 문자열 금지만으로 환각 여부를 판정하지 말고 근거와 의미를 함께 검토합니다.

어투·복수 발화·정정·생략·중복 전송·혼합 문의도 평가합니다. `conversation`과 `input.text`, [대표 대화 미리보기](samples/dm-examples.md)의 일치 여부를 자동 검사하며, 대화 원본은 실제 수집 DM이 아닌 가상 자료입니다. AC-22~23의 의미·분류 품질은 서비스 구현 후 별도로 실행합니다.

[인수조건](acceptance-criteria.md)의 모든 AC를 실행 결과에 연결합니다. DM만으로 만들 수 없는 동시 확정·재내보내기·자료 버전 충돌·주소 API 장애는 별도 서비스 시나리오로 작성합니다.

## 품질 평가 기준

실제 비식별 DM 50건을 평가 전 고정하고 정답·유형·관련 필드를 사람이 확인합니다. 기준은 분류 90% 이상, 초안 사용 가능 70% 이상, 근거 없는 생성 0건, 필드 추출 95% 이상, 누락 감지 100%입니다. 사례 분포·분모·미검사 수를 함께 기록합니다.

연락처·주소·SKU·수량·입금자명은 정규화 규칙을 정한 뒤 비교합니다. 초안 문장 전체 일치는 요구하지 않으며 사실성·누락·사용 가능 여부를 검토합니다. 누락 사례나 생성 초안이 없으면 해당 비율을 통과로 계산하지 않습니다.

실사용은 도입 전후 동일 업무의 시간을 기록하고 복사·검토·수정 시간도 포함합니다. 실제 고객 자료 권한과 보관 기준이 정해지기 전에는 실행하지 않습니다.

## 결과 기록 양식

실행 ID / 날짜 / 코드·자료·모델·프롬프트 버전 / AC 또는 DM ID / 기대값 / 실제값 / 통과·실패·미실행 / 오류 근거 / 수정 사항을 기록합니다. 지연·비용도 측정하되 목표 상한은 현재 미정입니다. 실행 명령은 구현 후 이 문서와 README에 함께 추가합니다.

## 현재 수행한 자료 검사

2026-11-05 `python3 docs/samples/validate.py`로 상품 4종·SKU 6개·주문 6건·DM 40건·분석 출력 1건·발송 계약 예시 1건·Markdown 17개의 자료 검사를 수행합니다. `python3 -m unittest discover -s docs/tests -v`는 [회귀 검사](tests/test_validate.py)를 실행합니다.

회귀 범위: 정상 자료·품목 순서 변경·과거 단가/할인/배송비 변경 허용, SKU·상품 연결·가격·수량 변조 거절, 중복 품목·실수/불리언 숫자·근거 스냅샷 오류·잘못된 과거 합계·음수/과도한 할인 거절, 발송 명령 예시의 미확정 주문·필수값·버전·확정 전/미래/시간대 없는 시각·재고 변경 표시 오류 거절, 중복 SKU·깨진 링크 거절입니다.

추가 회귀 범위: 대화 원본과 분석 입력 불일치, 허용하지 않는 발화 역할, 판매자로 끝나는 입력, 미리보기와 원본 불일치, 완전한 출력의 수령인 추출값 변조를 거절합니다.

## 현재 수행한 백엔드 검사

`npm test`의 20개 Node 테스트로 SQLite 재시작 보존·백업 복구·자료 적재 반복 안전성·판매자/고객/방 격리·요청 중복·HTTP 입력/본문/출처/인증/빈도 제한·금액 계산·문서 경로/심볼릭 링크 차단·XLSX 검증/원자성·MCP SDK 클라이언트 호출·Flue 도구 실행·환경 변수 우선순위를 확인합니다. `npm run typecheck`, `npm run lint`, `npm run format:check`, `npm run build`도 실행합니다. 기존 Python 회귀 검사는 31개입니다.

컴파일된 서버를 실제 로컬 소켓으로 띄워 방 생성 → 채팅 수신 → 모델 미연결 응답 → 중복 재전송 → 메시지 조회 → 서버 재시작 후 보존을 확인했습니다. 별도 MCP stdio 프로세스에도 SDK 클라이언트를 연결해 도구 6개 열람·62,000원 견적·허용 파일 실제 읽기·방 미설정 주문 조회 거절을 확인했습니다. 임시 DB와 프로세스는 검사 후 정리했습니다.

추적 범위는 DM-002 / R-06 / AC-04의 금액 계산 부분, DM-009 / R-08 / AC-12의 후보 조회 부분, R-10의 자료 격리 기반입니다. 도구 단독 검사는 DM 전체 분석이나 해당 AC 전체 통과를 뜻하지 않습니다.

자동 테스트 중 Flue 검사는 실제 실행 루프에 스크립트 공급자를 연결해 방 맥락 분리·자료/계산 호출·검증 없는 결과 거절·모델 호출 상한·시간 초과 중단·실패 캐시를 검사합니다. 추가로 SQLite 실행 기록 재시작, 자료 버전 변경 거절, 같은 방 동시 요청 제한, TypeSafe 요청/응답 검증, 컨테이너 인증 조건을 검사합니다. 스크립트 공급자는 테스트에만 주입하며 제품 설정에는 없습니다.

`npm run verify:agent`는 env의 실제 키를 사용하는 유료 검사입니다. 고정 가상 기준 시각 2026-11-05, 격리된 앱 메모리 DB·임시 Flue DB, 이전 베이지 주문 후 크림 추가 입력으로 실제 Flue → OpenAI → TypeSafe/상품/정책/견적/제출을 실행했습니다. 62,000원을 독립 대조하고 같은 요청의 모델 호출 수 불변·주문/재고 원본 보존을 확인했습니다. 이는 DM-002 / R-06 / AC-04의 연결·금액·읽기 경계 부분 검사이며 사례 전체나 다른 AC 통과가 아닙니다. 원문·키는 결과 로그에 남기지 않고 HTTP 상태·도구 이름/성공·모델 호출 수·지연만 출력합니다.

Docker 이미지 빌드·Bearer 없는 요청 `401`·인증된 health/방 생성·사진 전용 입력·컨테이너 재시작 후 메시지 보존도 확인했습니다. 컨테이너의 컴파일된 실행기로 실제 연결 검사를 다시 수행해 `200 / awaiting_payment`, 모델 6회·TypeSafe/자료/견적/검증 제출 성공·62,000원·재전송 추가 호출 없음·원본 보존을 확인했습니다. 최종 가상 주문 검증 지연은 약 20.6초이며 실제 청구 금액은 측정하지 않았습니다. 검사 전용 Compose 프로젝트·볼륨은 종료·정리합니다.

가상 40건 전체의 도구 선택/분류/추출/답장 품질, 화면 E2E, 주문 승인/발송 상태 변경·재고 동시 차감·주소 API·택배 업로드·실제 50건 평가와 제품 전체 AC 통과는 미실행입니다.
