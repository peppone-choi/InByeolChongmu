# 아키텍처와 외부 연동 설계

상태: Hono·TypeScript·파일 SQLite, Flue/OpenAI 실행·TypeSafe 분류·자료 도구·React 검토 화면·상품/정책 수정과 Docker 단일 서버 실행을 구현했습니다. 주문 후보 저장·판매자 승인·발송/정정·택배 내보내기·실제 고객 운영 배포는 미구현입니다. 구현 계약은 [백엔드 사용법](backend.md)을 따릅니다.

## 처리 흐름

`입력 검증 → 문의 분류 → 상품·주문 후보 조회 → 구조화 추출 → 코드 검증·금액 계산 → 초안 작성 → 근거 대조 → 검토 화면`

기능 분리는 책임 구분이며 단계마다 별도 모델 호출·에이전트·서비스를 강제하지 않습니다. 초기 구현은 화면에 의존하지 않는 단일 백엔드 코어와 채팅 수신 HTTP API·CLI 실행으로 시작합니다. `POST /api/chat`과 CLI는 같은 수신 서비스를 사용하며 현재는 대화방·메시지를 저장한 뒤 Flue가 OpenAI와 자료 도구를 호출해 검증된 분석을 반환합니다. 키 없는 기본 설정에서는 미연결을 반환합니다. 자료 조회·코드 계산은 같은 도구를 HTTP·CLI·Flue·MCP에서 호출합니다. 현재 `web/`은 React·Vite 검토 화면이며 동일 출처 채팅 API와 연결합니다. 방·분석·도구 기록의 원본은 SQLite이고 개발 프록시/빌드 세션은 서버 인증을 담당합니다. 구체적인 순서는 [구현 계획](implementation-plan.md)을 따릅니다.

## 실행기와 연결 계층

사용자 지정에 따라 현재 주 실행기는 Flue입니다. Jev는 실제 분류 도구로 연결했습니다. Hermes·OpenAI Agents API의 비교·보조 역할과 AI Gateway 추론 라우팅은 후속입니다. 실행기와 관계없이 상품·정책·주문·업무 일정·문서 조회는 같은 판매자 범위와 근거 계약을 사용합니다. 자료별 연결 대상과 도구 목록은 [구현 계획](implementation-plan.md)에서 관리합니다.

게이트웨이의 일반 모델 호출 지원과 Agents API 세션·Jev 경로의 호환성은 별개입니다. 앱의 자료 접근 권한도 Codex의 연결 상태에서 자동 상속되지 않습니다. 공식 API/MCP와 서비스 전용 인증을 확인한 뒤 연결 완료로 표시합니다.

## 구성 요소의 책임

- 입력 경계: 판매자 문맥·고객 경계·입력 크기·사진 전용 여부를 확인합니다.
- 자료 어댑터: 상품·정책·주문을 공통 형식으로 읽고 ID·버전을 반환합니다. 첫 구현은 가상 JSON, Google Sheets 등 실제 연결은 별도 선택입니다.
- 모델 처리: 분류·추출 후보·답장 초안을 작성합니다. 주문 상태 쓰기·입금 확인·가격 결정·외부 발송 권한을 갖지 않습니다.
- 코드 검증: 스키마·필수값·상품 후보·정수 금액·마감·재고·근거 수치를 확인합니다. 주관적 착용감과 문장 전체의 진실성을 자동 보장하지 않습니다.
- 주문 서비스: 후보 저장과 승인 명령을 분리합니다. 신뢰 가능한 승인 문맥·최신 버전·멱등성·원자성을 보장할 저장소가 필요합니다.
- 발송 기록: 판매자가 수동 등록·정정하는 명령을 주문 서비스에 둡니다. 송장·발송일과 감사 기록을 함께 저장하며 재고·금액은 변경하지 않습니다. 모델과 내보내기 경로에서 이 명령을 자동 실행하지 않습니다.
- 출력 어댑터: 초안·근거를 화면에 표시하고, 택배 양식으로 변환합니다. 출력은 별도 외부 발송을 유발하지 않습니다.

## 신뢰 경계와 실패 처리

DM·외부 셀 내용·모델 출력은 신뢰하지 않는 입력입니다. 이 안의 지시문을 도구 실행이나 정책 변경으로 해석하지 않습니다. 비밀 키는 클라이언트나 모델 문맥에 넣지 않습니다.

자료 조회 실패·모델 실패·출력 검증 실패는 정상 초안과 분리합니다. 무제한 재시도하지 않고 요청별 오류와 재시도 가능 여부를 남깁니다. 분석 재시도로 주문 확정 명령이 재실행되지 않도록 경계를 분리합니다.

## 외부 연동 계약 뼈대

- 상품·정책·주문: 읽기와 쓰기 권한 분리, 자료 버전 충돌 처리, 동시 수정 시 재확인.
- 주소 검색: 기본 추출 이후 후보 확인용. 가상 샘플은 호출 금지, 이름·연락처 전송 금지, 실패·복수 후보를 통과로 처리하지 않음.
- 택배: 실제 업로드 양식 버전·필수 열 확보 후 구현. API 송장 발급은 범위 밖.
- 모델: 모델·프롬프트 버전, 구조화 출력 지원, 지연·비용을 가상 자료로 비교한 뒤 선택.

## 기술 결정 전 검증

단순 시트 쓰기만으로 동시 확정과 재고 차감의 원자성을 보장한다고 가정하지 않습니다. 저장소 선택 시 AC-09~11을 충족하는지 먼저 확인합니다. API 경로·인증·배포 구성이 정해지면 이 문서와 입출력 명세를 확장합니다.
