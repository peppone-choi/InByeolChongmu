# 가상 샘플 자료

모든 계정·인물·연락처·주소·송장·상품·가격·정책은 제작용 가정입니다. 실제 고객 자료가 아니며 외부 전송·주소 API 조회·전화·택배 접수에 사용하지 않습니다. 주소는 실제 조회에서 성공하지 않도록 가상 지명을 사용했습니다.

## 파일과 고정 조건

- [상품표](products.json): 상품 4종, SKU 6개, 가격·재고·실측·별칭·마감. `material=null`과 중복 별칭은 의도된 사례입니다.
- [판매 정책](policies.json): 배송비·할인·수동 입금 확인·출고일·예외·말투의 6가지 가정.
- [주문 기록](orders.json): 발송 1건, 확정 3건, 입금 대기 1건, 취소 1건. 동명이인 2명을 포함합니다.
- [DM과 기대 항목](dm-cases.json): 입력 40건과 필수 검증 항목. 문의 6유형 외에 사진 전용·입력 오류를 포함합니다.
- [읽기 쉬운 대화 예시](dm-examples.md): JSON 원본에서 뽑은 대표 8건. 고객·판매자 어투와 문맥별 기대 판단을 함께 봅니다.
- [완전한 분석 출력](analysis-example.json): DM-002의 계약 예시. 실제 모델 실행 결과가 아닙니다.
- [수동 발송 명령](shipment-example.json): SHIP-001의 등록 요청·기대 응답. O-0002를 참조하며 실제 주문 상태나 재고는 바꾸지 않습니다.

기준 판매자는 `sample-seller-01`, 시각은 `2026-11-05T10:00:00+09:00`입니다. `synthetic=true` 표시는 데이터 파일의 메타데이터이며 분석 요청 계약 자체의 필드는 아닙니다. 각 DM은 같은 초기 스냅샷에서 독립 실행합니다.

## 샘플 가격 규칙

금액 단위는 원, 샘플 가격은 세금 포함 가정입니다. 주문당 배송비는 3,000원이며 무료배송·지역 추가금은 없습니다. P001 수량 합계가 2개 이상이면 주문당 3,000원을 한 번 할인하고 다른 상품 수량은 합산하지 않습니다.

DM-002는 K-BE 31,000원 + K-CR 31,000원 − 할인 3,000원 + 배송비 3,000원 = **62,000원**입니다. DM-019의 99개 견적은 **3,069,000원**이지만 가용 재고 4개를 초과하므로 확정할 수 없습니다.

현재 재고는 기존 확정·발송·취소 주문을 이미 반영한 스냅샷입니다. 주문 파일 적재를 재고 차감 명령으로 해석하지 마세요. 과거 주문은 당시 가격을 보존하며 현재 마감 여부와 구분합니다.

과거 주문 금액은 저장된 단가·할인·배송비의 정수 범위와 산술을 검사합니다. 현재 가격·정책으로 다시 계산하지 않습니다. 과거 정책에 맞는 할인인지까지 확인하려면 당시 정책 버전이 추가로 필요합니다.

## 사례 묶음

- DM-001~007: 상품·주문·누락·미특정·출처 없음·품절·마감.
- DM-008~013: 배송 조회·동명이인·기록 없음·클레임·광고·사진.
- DM-014~020: 지시문 주입·잘못된 번호·0개 수량·별칭 충돌·입금 주장·재고 부족·빈 아이디.
- DM-021~027: 여러 메시지 주문·옵션/연락처/주소 정정·스토리 참조·맥락으로 뜻 복원·비침/착용감 문의.
- DM-028~034: 다른 입금자·입금액 차이·확정 주문 주소 변경·취소·교환·마감 예외·배송 문의와 새 주문의 혼합.
- DM-035~040: 가격 흥정·대화와 정책의 충돌·인사·여러 상품과 한글 수량·수량 미정·동일 주문 재전송.

## 대화와 어투 설계

각 사례의 `scenario`는 장면, `tags`는 특징, `conversation`은 순서가 있는 고객·판매자 발화입니다. `input.text`는 `[고객]`, `[판매자]`를 붙여 이어 쓴 분석용 문자열입니다. 공식 인스타그램 내보내기 형식이 아니며, 이 역할 표기는 권한이나 진짜 판매자임을 증명하지 않습니다. 사진은 `input.attachments`에만 기록하고 내용을 추론하지 않습니다.

친근한 호칭, 짧은 메시지, 이모지, 초성·오타·띄어쓰기 생략과 정중한 문장을 섞었습니다. 모든 고객을 같은 말투로 만들지 않습니다. 최신의 명시적 정정은 후보에 반영하되, 미정인 수량·사라진 스토리 맥락은 추측하지 않습니다. 기존 확정 주문의 변경 요청은 자동 적용하지 않습니다.

참고한 [「인스타 공구 말투 특징」](https://m.blog.naver.com/3345/223815606562)은 2026-11-05 본문과 첨부 이미지 18장을 확인했습니다. 친근한 호칭·반존대·하트/합장 이모지·판매 촉구 표현을 참고했지만, 글은 풍자·패러디이며 실제 거래 DM 표본이 아닙니다. DM-036의 판매자 발화는 이를 참고해 새로 쓴 가상 예시입니다. 할인 약속과 마감 압박을 사실이나 승인으로 받아들이지 않는 판단도 함께 검증 대상으로 남깁니다.

`expected`는 전체 응답 JSON이 아닌 필수 검증 항목입니다. `matched_skus`, `quantities`, `total_krw`는 실제 출력의 `order_draft` 등에서 비교하는 평가용 편의 키입니다. `evidence_required`는 근거 ID를, `must_not_claim`은 금지 의미를 확인합니다. 초안 문장 전체 일치를 요구하지 않습니다.

`extracted_fields`는 기대 추출값을 필드 경로와 값으로 적은 평가용 항목이며, `notes`는 복합 문의·정정·예외를 판단할 때의 검토 기준입니다. DM-002의 추출 기대값은 완전한 출력 예시와 자동 대조합니다. 다른 대화의 의미·어투·분류 기대값은 아직 모델로 평가하지 않았습니다.

실제 주소 검색 성공·통신 장애·동시 확정·반복 명령·실제 엑셀 업로드는 이 파일만으로 검증되지 않습니다. 별도 모의 의존과 서비스 테스트가 필요합니다. 실제 DM 50건 품질 목표를 이 가상 자료로 대체하지 않습니다.

## 자료 검사

저장소 루트에서 Python 3로 `python3 docs/samples/validate.py`를 실행하세요. JSON·식별자 참조·금액·기대값·완전한 출력 예시·문서 링크를 검사합니다. 모델 응답이나 제품 동작을 실행하지 않습니다.

`python3 -m unittest discover -s docs/tests -v`로 검사 도구의 회귀 검증을 실행합니다. 임시 복사본만 변경하며 원본 JSON을 보존합니다. 분석 품목은 상품표·기대 수량과 대조하고, 금액은 신뢰한 자료로 재계산합니다. 발송 예시는 명령 필수값·버전·시각·기대 응답을 검사할 뿐 멱등성·동시성·저장 트랜잭션을 실행하지 않습니다.

대화 원본·분석 입력·Markdown 미리보기의 동기화도 검사합니다. 갱신은 `validate.py`의 `render_conversation`과 `dm_preview` 함수를 사용하세요. 기본 검사 명령은 파일을 재작성하지 않고 불일치하면 실패합니다.
