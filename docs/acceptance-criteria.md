# 인수조건

상태: 초안, 전 항목 미실행. 아래 조건은 Given(전제)·When(행동)·Then(결과) 형식이며 문서 작성 완료와 제품 인수 통과를 구분합니다.

## 입력·분류·초안

- **AC-01 / R-01·02**: `DM-001`을 입력하면 `product_inquiry`로 분류하고 K-BE 재고·실측·할인 근거를 제시합니다. `DM-020`의 빈 아이디는 `invalid_input`으로 안내하며 모델 처리에 넘기지 않습니다.
- **AC-02 / R-03·04**: `DM-004·005·017`을 입력하면 미특정·출처 누락·별칭 충돌을 구분합니다. 상품·소재를 지어내거나 충돌 후보 하나를 임의 확정하지 않습니다.
- **AC-03 / R-02·04**: `DM-011` 클레임은 높은 우선순위와 판매자 확인으로 표시합니다. `DM-012·013`은 초안이 `null`이고 광고 응답·사진 추론을 하지 않습니다.

## 추출·계산

- **AC-04 / R-05·06**: `DM-002` 입력의 두 품목·수령인·입금자명을 추출하고 상품합 62,000원 − 할인 3,000원 + 배송비 3,000원 = 총 62,000원을 반환합니다. 입금 주장과 실제 확인은 구분합니다.
- **AC-05 / R-05·06**: `DM-003`은 연락처·입금자명 누락을, `DM-015·016`은 잘못된 연락처·0개 수량을 안내합니다. 잘못된 수량의 금액은 계산하지 않습니다.
- **AC-06 / R-06**: `DM-006·007·019`는 품절·마감·재고 부족으로 사람 확인 대상이 됩니다. 계산값이 있어도 확정 가능을 뜻하지 않습니다.
- **AC-07 / R-06·12**: 가격·수량·실측의 불일치를 주입하면 검증 실패를 표시합니다. JSON 파싱 실패·검사 미실행을 정상 결과로 표시하지 않습니다.

## 주문 상태와 조회

- **AC-08 / R-07**: `DM-002·018` 분석 전후 주문과 재고 스냅샷이 같습니다. 고객의 입금 주장만으로 `confirmed`로 바뀌지 않습니다.
- **AC-09 / R-07**: 유효한 대기 주문에 판매자 확인·최신 버전·동일 금액을 갖춘 확정 명령을 보내면 주문 확정과 모든 품목 차감이 한 번에 완료됩니다. 하나라도 실패하면 주문·재고 변경이 모두 취소됩니다.
- **AC-10 / R-07**: 같은 확정 명령 키를 반복하면 기존 결과를 돌려주고 재차 차감하지 않습니다. 같은 키의 다른 내용은 충돌로 거절합니다. 서로 다른 키로 같은 주문을 확정해도 차감은 한 번입니다.
- **AC-11 / R-07**: 동일 재고 마지막 1개를 두 주문이 동시에 확정하면 최대 한 건만 성공합니다. 초안 생성 후 가격·마감·재고가 바뀌면 재검토를 요구하고 조용히 새 가격을 확정하지 않습니다.
- **AC-12 / R-03·08**: `DM-008`은 O-0001 기록의 송장·발송일만 답하고 실시간 배송을 주장하지 않습니다. `DM-009`는 두 후보를 보여 주되 초안은 `null`, `DM-010`은 조회 실패와 추가 확인 질문을 반환합니다.

## 일괄 처리·내보내기·운영

- **AC-13 / R-09**: 초기 주문 스냅샷에서 O-0002·0003·0006만 내부 내보내기 후보가 됩니다. 미입금·취소·기발송 건은 제외 이유를 표시합니다. 선택 양식의 추가 필수값이 없으면 해당 건을 내보내지 않습니다.
- **AC-14 / R-09**: 실제 택배 양식 확보 후 열·자료형·필수값을 대조하고 가상 자료로 파일을 검증합니다. 재내보내기도 자동 발송·재고 차감·상태 전환을 하지 않으며 이전 내보내기 이력을 알려 중복 접수를 주의시킵니다.
- **AC-15 / R-01·10**: DM-001·002·009·020을 묶어 입력해도 계정·주소·근거가 서로 섞이지 않습니다. 실패 건만 재시도하며 다른 건을 재확정하지 않습니다.
- **AC-16 / R-11·12**: `DM-014`의 정책 무시 지시를 실행하지 않습니다. 로그에서 주소·연락처·본문이 노출되지 않고, 자료 버전·오류 코드로 실패 위치를 확인할 수 있습니다.
- **AC-17 / R-06·12**: 주소 조회를 호출하지 않거나 모의 실패·복수 후보를 반환하면 각각 별도 상태를 표시합니다. 원문 주소를 덮어쓰거나 검증 완료로 바꾸지 않습니다.

## 수동 발송 기록 (서비스 구현 후 검증)

- **AC-18 / R-08·13**: O-0002 확정 주문에 SHIP-001의 유효한 수동 등록을 실행하면 `shipped`, 버전 2와 송장·발송일이 함께 저장됩니다. 이후 조회에서 해당 기록이 보이고 재고·금액은 그대로입니다. 현재는 명령 예시 정합성만 검사하며 서비스 동작은 미실행입니다.
- **AC-19 / R-13**: 다른 판매자 주문, 미확정·취소 주문, 빈 택배사·송장, 시간대 누락, 확정 전 또는 미래 발송 시각, 오래된 버전을 거절합니다. 어떤 실패에서도 부분 기록·상태 변경·재고 차감이 없어야 합니다.
- **AC-20 / R-07·13**: 최초 등록의 동일 키·같은 요청을 재전송하면 기존 응답을 재사용합니다. 새 키의 최초 등록을 이미 발송된 주문에 보내면 거절하고, 같은 키의 다른 요청은 충돌로 거절합니다. 동시에 들어온 등록 중 하나만 반영합니다.
- **AC-21 / R-12·13**: 최신 버전의 발송 주문에 정정 사유를 갖춘 `update_shipment`를 실행하면 상태는 `shipped`, 버전은 +1이고 변경 전후·사유·승인자·시각이 남습니다. 빈 사유·충돌·저장 실패는 거절하거나 전부 롤백하며 동일 요청 재시도는 다시 수정하지 않습니다.

## 인수 통과 조건

기능 조건을 실제 실행한 증거와 결과가 있어야 통과입니다. 품질 수치·실사용 효과는 [검증 계획](test-plan.md)에서 별도로 판정합니다. 실제 양식·화면·실행 코드가 없는 현재는 통과 판정하지 않습니다.
