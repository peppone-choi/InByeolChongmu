# 구현 순서와 결정 목록

상태: 제작 준비 초안. 사용자의 방향에 따라 백엔드·에이전트를 먼저 구현하고 화면은 뒤로 미룹니다. 실행 코드·모델 연결·DB·제품 검증은 아직 없습니다.

## 다음 작업: 서비스 기반 부트스트랩

### 목표와 확정 조건

사용자는 **실제 서비스로 이어갈 기반**과 **백엔드·에이전트 우선, 화면 후속**을 선택했습니다. 첫 산출물은 가상 DM을 받아 실제 모델이 필요한 상품·정책·주문 자료를 조회하고, 코드 검증을 거친 구조화 결과와 근거 있는 답장 초안을 반환하는 실행 가능한 에이전트입니다. 채팅 수신 HTTP API와 CLI가 같은 에이전트 코어를 호출하도록 만들고, 웹 화면은 첫 완료 조건에서 제외합니다.

단일 판매자, 답장 직접 전송, 판매자 입금 확인·주문 확정, 기존 MVP 기능과 제외 범위는 유지합니다. 개발은 로컬·가상 자료를 기본값으로 하고 실제 개인정보·외부 배포는 포함하지 않습니다. 고정 기대 출력의 재생을 실제 분석 기능으로 사용하지 않습니다.

### 구현 순서와 산출물

1. **최소 백엔드 실행 기반과 계약**: TypeScript strict·Node LTS·npm을 추천합니다. `src/domain`에는 입출력 스키마와 계산·검증 규칙, `src/agent`에는 모델과 도구를 연결하는 실행 흐름, `src/adapters`에는 자료·모델 연결, `src/cli`에는 실행·평가 진입점, `src/http`에는 채팅 수신 API를 둡니다. 필요한 린트·타입검사·단위 테스트만 함께 구성합니다. HTTP 서버 구성은 첫 단계에서 선택하되 화면 프레임워크·컴포넌트·브라우저 테스트는 아직 설치하지 않습니다. 런타임·패키지 버전과 잠금 파일은 실제 설치·검증 후 고정합니다.
2. **자료 조회 도구와 코드 검증**: 기존 JSON의 상품·별칭·정책·주문 조회를 읽기 전용 도구로 제공합니다. 도구 인자는 실행 시 검사하고 판매자 범위를 서버에서 정합니다. 입력 기준 시각과 자료 버전을 주입하며, 조회 자료는 모델 판단의 근거로만 사용합니다. 가격·할인·배송비 계산, 수량·옵션·누락 검사는 코드가 담당합니다. 분석 경로에 주문·재고 쓰기 도구를 연결하지 않습니다.
3. **실제 모델을 쓰는 단건 에이전트**: 입력 검증 → 문의 분류 → 필요한 도구 조회 → 구조화 추출 → 코드 검증·계산 → 답장 초안 → 근거 대조를 연결합니다. 모델이 자료 조회 도구를 사용할 수 있게 하되 호출 가능한 도구와 쓰기 금지는 코드로 제한합니다. 각 책임을 별도 에이전트나 별도 모델 호출로 강제하지 않습니다. 공급자·모델·SDK는 구조화 출력·도구 호출·실행 기록·비용·호환성을 비교해 첫 실제 호출 전에 결정합니다. API 키는 서버 환경에서만 읽고, 호출/토큰·도구 실행·재시도·시간·평가 비용 상한도 실행 전에 설정합니다. 이 작업은 현재 키 생성이나 과금을 수행하지 않습니다.
4. **채팅 API·CLI 실제 실행과 평가**: `POST /api/chat`으로 고객 아이디·대화 원문을 받아 실제 에이전트를 호출하고 `io-spec.md` 형식의 JSON 결과를 반환합니다. CLI도 같은 코어를 사용합니다. HTTP 요청 검증·오류 응답·크기/시간 제한을 서버 경계에서 처리하고 판매자·기준 시각·자료 버전은 서버가 정합니다. 첫 API는 요청에 필요한 앞 대화까지 함께 보내는 동기식 처리로 제안하며, 서버 대화 이력 저장·스트리밍은 후속으로 둡니다. 구체적인 HTTP 계약은 [입출력 명세](io-spec.md)의 1.1절을 따릅니다. 먼저 정상 주문·정보 누락·상품 모호·주문 후보 충돌·입금 주장·DM 속 지시문 공격을 실제 모델로 실행합니다. 이후 가상 DM 40건을 평가하고 사례별 결과·오류·근거·지연·사용량과 비용을 기록합니다. 실제 비용을 얻지 못한 경우 추정값과 구분합니다. 모델 없는 단위 테스트와 실제 모델 평가는 명령·결과를 분리합니다.
5. **주문 백엔드와 승인 API 확장**: 읽기 기반 에이전트의 첫 검증 후 논리 모델을 PostgreSQL·Drizzle 추천안으로 구체화하고 마이그레이션·가상 seed를 만듭니다. 승인자 문맥, 최신 가격·정책·재고·버전 재검사, 중복 명령과 동시성·원자성부터 검증합니다. 이후 후보 저장·조회·판매자 확정·수동 발송 명령과 로컬 API를 연결합니다. 모델에는 자동 확정 권한을 주지 않습니다. 이미 구성한 HTTP 서버에 주문 명령 경로를 추가하고 분석 API와 승인 명령의 권한을 분리합니다.

1~4가 첫 부트스트랩의 완료 범위이며 5는 다음 백엔드 단계입니다. DB 상세 설계와 거래 안전성 검사는 주문 쓰기 구현의 선행조건이지, 읽기 전용 에이전트 검증의 선행조건은 아닙니다.

### 첫 부트스트랩 완료 기준

- 새 설치에서 잠금 파일로 실행 환경을 재현하고 채팅 API와 CLI 양쪽으로 가상 DM을 처리할 수 있습니다. 정상 요청은 실제 에이전트 결과를 반환하고, 잘못된 입력은 모델 호출 전에 거절하며, 모델 실패·시간 초과는 정상 결과와 구분합니다. HTTP 통합 검사도 완료 조건에 포함합니다. 환경 예시에는 비밀 값이 없으며 로컬 설정과 실제 DM·주소·전화번호를 커밋하지 않습니다.
- 입력·모델 출력·도구 인자를 실행 시 검증합니다. 자료·모델·검증 실패는 `failed` 등 계약상의 오류로 반환하며 미검사를 통과로 표시하지 않습니다. 빈 아이디 등 입력 오류는 모델 호출 전에 거절합니다.
- DM-002를 실제 처리한 결과가 상품합 62,000원 − 할인 3,000원 + 배송비 3,000원 = 총 62,000원과 일치합니다. 모델이 제안한 금액을 정답으로 사용하지 않습니다. DM-003의 누락, DM-004·017의 상품 모호성, DM-009의 주문 후보 충돌을 임의로 채우거나 확정하지 않습니다.
- DM-014의 정책 무시 지시와 DM-018의 입금 주장이 정책 변경·주문 확정·재고 변경으로 이어지지 않습니다. 분석 전후 자료가 같고, 실제 호출 기록으로 도구 조회와 검증 단계가 실행됐는지 확인합니다. 기대값·해설·태그는 평가기만 읽고 에이전트 입력에 주지 않습니다.
- 가상 40건의 분류·추출·누락·근거 오류를 정답과 독립 대조해 결과와 미달 항목을 남깁니다. 금액 일치만으로 답변 전체의 사실성을 보장하지 않습니다. 승인 경계 위반·근거 없는 자동 확정 등 차단 실패가 있으면 완료로 보고하지 않습니다.
- 실제 과거 DM 50건의 분류 90%·초안 사용 가능 70%·근거 없는 정보 0건·추출 95%·누락 감지 100% 목표는 별도입니다. 가상 평가로 달성했다고 보고하지 않으며, 사람이 판단할 초안 적합성을 자동 평가만으로 확정하지 않습니다.
- 설치·빌드·린트·타입·테스트·단건 실행·가상 평가의 정확한 명령을 실제 구현 후 README에 기록합니다. CI는 비밀 키 없이 실행하는 코드·자료 검사를 기본으로 하고 실제 모델 평가는 명시적으로 실행·기록합니다. 현재는 앱 명령이 없습니다.

### 후속 단계와 미룬 이유

- **웹 검토 화면·디자인·Playwright**: 실제 결과 계약과 오류 동작을 검증한 다음 그 결과를 표시합니다. 고정 예시 화면 제작을 에이전트 개발보다 앞세우지 않습니다. Next.js는 현 단계의 필수 선택에서 뺍니다.
- **PostgreSQL·Drizzle·Docker Compose**: 주문 쓰기 단계의 추천안으로 유지하며 아직 설치·채택하지 않았습니다. 로컬 JSON으로 읽기 도구를 검증하고, 저장 기능 구현 전 DB 엔진·스키마·트랜잭션 검증을 마칩니다. 샘플 재고는 기존 주문 반영 후 스냅샷이므로 seed 시 재차 차감하지 않습니다.
- **여러 건 처리·택배 엑셀·주소 API·Sheets**: 단건 에이전트·주문 백엔드 다음에 연결합니다. 첫 MVP 범위에서 삭제하지 않으며 실제 양식·연동 조건을 먼저 확인합니다.
- **운영 인증·외부 배포·백업/복구**: 실제 자료·공개 서비스 사용 전에 갖춥니다. 개발용 고정 판매자 문맥을 운영 인증으로 쓰지 않습니다.

### 사용자 결정과 다음 행동

현재 필요한 방향은 서비스로 이어갈 기반, 백엔드·에이전트 우선으로 정해졌습니다. 호스팅·택배사·화면 디자인을 지금 추가 질문하지 않습니다. 다음 구현의 출발점은 입력·출력 계약과 읽기 도구를 갖춘 백엔드 코어이며, 첫 완료 시연은 채팅 API 요청부터 실제 모델·도구 조회·검증·JSON 응답까지의 전체 흐름입니다. CLI는 같은 코어의 개발·평가 진입점입니다. 모델 호출 전에는 사용할 공급자·모델·자격 증명 경로·비용 상한을 구체화합니다.

### 마피아 MCP 적용 근거

기존 `plan` 절차를 유지하고 사용자 수정에 따라 우선순위·구현 경계·검증 방법의 세 지점을 각각 다시 검색했습니다. 관련 카드의 일반 판단만 적용하며 카드가 특정 스택이나 구현 순서를 정해 준 것으로 해석하지 않습니다.

- 「선행조건을 걸기 전에 누구에게 걸리는 조건인지 가리고, 독립된 작업은 병렬로 둔다」 (`k1d36022857`): DB 거래 검증은 주문 쓰기에 필요하며, 읽기 에이전트와 실제 모델 검증을 막는 조건으로 두지 않습니다. 화면은 사용자의 지시에 따라 미룹니다.
- 「같은 수작업이 반복되면 기능보다 자동 반영 장치를 먼저, 흔하고 단순한 구조로 만든다」 (`kf40af93477`): 피해야 할 결과와 검증 방법을 먼저 정하고 프로젝트 규모에 맞는 최소 실행·평가 환경을 둡니다.
- 「동작 확인을 사용자에게 넘기기 전에 브라우저 자동화로 직접 end-to-end 테스트한다」 (`k82f4ec7618`): 직접 실행 후 보고한다는 일반 원칙을 적용합니다. 지금 브라우저 화면을 새로 만들라는 뜻으로 해석하지 않고 CLI에서 모델·도구·검증까지 실행합니다.

사용자의 채팅 수신 API 추가에 따라 수신 경로를 첫 부트스트랩에 포함했습니다. 마피아 MCP에서 범위를 재검색했으며 「배포 후 동작 확인과 테스트 데이터 정리를 사용자에게 넘기지 않고 끝까지 직접 한다」 (`ka6807a6552`)의 직접 검증 원칙을 로컬 HTTP 요청부터 에이전트 응답까지 확인하는 기준에 적용합니다. 배포·DB·화면을 먼저 만들라는 의미로 적용하지 않습니다.

## 전체 구현 순서

1. **채팅 API·백엔드 계약·읽기 도구·실제 모델 단건 에이전트**: 위 첫 부트스트랩 1~4와 가상 40건 평가를 수행합니다.
2. **주문 백엔드·저장소·API**: 후보 저장과 확정을 분리하고 AC-09~11의 권한·멱등성·동시성·롤백, UC-06 및 AC-18~21의 수동 발송·정정을 검증합니다.
3. **판매자 검토 화면**: 검증된 백엔드에 UC-01~03·06의 입력·근거·수정·복사·승인 흐름을 연결하고 브라우저에서 검증합니다.
4. **일괄 처리·택배 내보내기**: 고객 격리·건별 실패를 검증하고 실제 양식 확보 후 출력 어댑터를 구현합니다.
5. **실제 자료·운영 검증**: 셀러 정책·사용 권한·보관 기준·인증·복구 조건을 갖추고 실제 DM 50건 평가와 1주 사용 검증을 진행합니다.

## 지금 유지하는 결정

- D-01: 첫 버전은 DM 수동 입력·직접 발송·수동 입금 확인. 근거는 원문 기획입니다.
- D-02: 분류·추출·초안을 분리하고 숫자·상태 변경은 코드로 검증합니다. 근거는 전달받은 피드백과 오류 비용입니다.
- D-03: 초기 제작 자료는 가상 JSON으로 제공합니다. 실제 판매 정책·개인정보로 오해하지 않도록 표시합니다.
- D-04: 문서별 책임을 나누되 오류·운영·결정 기록은 관련 문서에 합쳐 관리합니다. 근거는 마피아 MCP 검토와 초기 프로젝트 규모입니다.

## 미정 사항과 결정 시점

- 실제 셀러·상품 정책·택배사 양식: 실제 업무 검증과 출력 어댑터 구현 전에 확인합니다. 가상 자료 작업은 진행할 수 있습니다.
- 모델·SDK·호출 상한은 첫 모델 실행 전에, 저장소·스키마는 주문 쓰기 전에, HTTP 프레임워크는 첫 부트스트랩의 채팅 API 구성 전에, 호스팅은 외부 배포 전에 결정합니다. 선택 기준은 구조화 추출, 도구 호출, 승인 원자성, 검증 편의, 비용·지연입니다.
- 입력 길이·일괄 건수·재시도·비용 상한: 가상 실행 측정 후 정합니다. 근거 없는 숫자로 고정하지 않습니다.
- 실제 개인정보 보관·삭제·외부 전송·운영 인증: 실제 자료를 받거나 외부 배포하기 전에 확정합니다.
- 확정 후 취소·환불·주소 변경 절차: 실제 판매자 사용 전 정합니다. 자동 처리 기능은 제외합니다.

## 추가 문서가 필요한 시점

HTTP API가 생기면 실제 엔드포인트·인증·오류 계약을 입출력 명세에 보강합니다. 외부 공개·다인원·고가용성 요구가 생기면 권한 모델·배포/복구 절차·운영 목표를 확장합니다. 지금은 존재하지 않는 기술의 설치법이나 인프라 구성을 만들지 않습니다.
