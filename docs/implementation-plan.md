# 구현 순서와 결정 목록

상태: Hono·SQLite·자료 도구·MCP에 이어 Flue 실행기를 채팅 API·CLI에 연결했습니다. OpenAI 직접 호출과 TypeSafe Jev 분류 도구의 가상 주문 연결 검증을 수행하며 Docker 단일 서버 실행을 제공합니다. 현재 명령·제한·동작은 [백엔드 사용법](backend.md)을 기준으로 합니다. Hermes·OpenAI Agents API·AI Gateway 추론 경로, 전체 DM 품질 평가와 주문 승인 기능은 후속입니다.

## 다음 작업: 서비스 기반 부트스트랩

### 이번 구현 범위와 저장소 결정

사용자가 키 설정과 실제 모델 검증을 미루고, 가능한 백엔드·채팅 API·SQLite·자료 조회 도구를 먼저 구현하도록 지정했습니다. Hono·TypeScript·파일 SQLite를 채택하고 `:memory:`는 테스트용으로 둡니다. 판매자는 DB를 다루는 대신 상품 XLSX 가져오기/내보내기를 사용할 수 있습니다. 서버 재시작 후 보존·원자적 상품 교체·방 분리·MCP 호출을 실제 검사합니다. 주문 확정/차감은 구현하지 않았으므로 SQLite를 쓴다는 이유로 AC-09~11 통과를 선언하지 않습니다. PostgreSQL·Docker를 필수로 요구하던 추천은 이 결정으로 대체합니다.

이후 사용자가 Flue 실행기·env 키·Docker 실행을 지정했습니다. 요청별 Flue 인스턴스와 불변 방 맥락, 앱/Flue 별도 SQLite를 사용합니다. 실제 OpenAI·TypeSafe 호출은 소량 가상 자료로 검증하며 기본 한도는 60초·모델 8회·도구 16회·출력 4,096토큰입니다. 이는 비용의 통화 상한이 아니며 전체 평가 전 측정값으로 조정합니다. 이하 실행기 비교와 전체 품질 평가는 후속 계획입니다. 자료 도구는 실제 SQLite와 허용 파일을 읽으며 고정 분석 결과나 정규식 분류로 모델을 대체하지 않습니다.

### 목표와 확정 조건

사용자는 **실제 서비스로 이어갈 기반**과 **백엔드·에이전트 우선, 화면 후속**을 선택했습니다. 첫 산출물은 가상 DM을 받아 실제 모델이 필요한 상품·정책·주문 자료를 조회하고, 코드 검증을 거친 구조화 결과와 근거 있는 답장 초안을 반환하는 실행 가능한 에이전트입니다. 채팅 수신 HTTP API와 CLI가 같은 에이전트 코어를 호출하도록 만들고, 웹 화면은 첫 완료 조건에서 제외합니다.

단일 판매자, 답장 직접 전송, 판매자 입금 확인·주문 확정, 기존 MVP 기능과 제외 범위는 유지합니다. 개발과 검증은 가상 자료를 기본값으로 하며 Docker 단일 서버 실행을 제공합니다. 실제 개인정보·공개 운영 배포는 포함하지 않습니다. 고정 기대 출력의 재생을 실제 분석 기능으로 사용하지 않습니다.

### 우선 활용할 에이전트 기술과 연결 검증

사용자가 지정한 기술 축은 **Flue·Jev·Hermes·OpenAI Agents API·AI Gateway**입니다. 직접 만든 모델 호출 루프만으로 끝내지 않고, 이 기술들의 실제 실행·도구 연결 기능을 우선 활용합니다. 다음은 공식 문서에 근거한 역할 배치와 검증 계획이며 설치·계정 접근·상호 호환성 확인을 마친 상태는 아닙니다.

- **Flue**: TypeScript 기반 주 실행기 후보입니다. 도구·MCP·Skills·상태 관리와 HTTP 진입 기능을 검증합니다. [공식 에이전트 문서](https://flueframework.com/docs/guide/building-agents/), [MCP 연결](https://flueframework.com/docs/guide/mcp/).
- **Jev (TypeSafe)**: 문의 유형·우선순위·다음 처리 경로처럼 정해진 선택지의 판단에 사용합니다. 텍스트 생성 모델을 대체하지 않으며, 구조화된 반환값도 판단의 정확성이나 정책 준수를 보장하지 않습니다. 한국어 DM과 모호한 입력에서 생성 모델 분류와 비교하고 불확실하면 확인 필요로 돌립니다. 금액 계산과 승인 권한은 계속 코드가 결정합니다. [공식 소개](https://docs.typesafe.ai/introduction).
- **Hermes (Nous Research)**: 문서·파일·MCP 도구·메모리·일정 실행을 활용할 실행기 후보입니다. 같은 자료 조회 업무를 실제 실행해 Flue·Agents API와 비교하고, 별도 운영 보조 역할이 필요하면 그 역할과 허용 도구를 구분합니다. 판매자 정책과 가격을 학습 메모리가 임의로 덮어쓰게 하지 않습니다. [공식 문서](https://hermes-agent.nousresearch.com/docs).
- **OpenAI Agents API**: 관리형 세션·도구/MCP·파일 작업과 실행 복구를 활용할 실행기 후보입니다. 단순 생성 API나 Agents SDK와 구분하고 실제 계정의 접근 권한·도구 결과 전달·세션 정리까지 검증합니다. 공식 문서상 세션 상태를 보관하고 미국 데이터 레지던시만 지원하며 ZDR을 지원하지 않으므로 실제 고객 자료 도입 전 적합성을 확인합니다. [공식 개요](https://developers.openai.com/api/docs/guides/agents-api/overview).
- **AI Gateway**: 지원되는 모델 요청의 사용량·비용·실패·호출 제한과 라우팅을 관리합니다. Cloudflare 기본 Gateway 계정 설정은 확인했으며 현재 OpenAI 직접 호출을 Gateway로 라우팅하는 작업은 후속입니다. Agents API의 세션 경로나 Jev를 일반 모델 프록시에 그대로 통과시킬 수 있다고 가정하지 않고 각각 검증합니다. 개인화 답변·최신 재고 응답은 초기 캐시 대상에서 제외하고, 요청/응답 본문 로그도 기본 수집하지 않는 구성으로 검토합니다. [Cloudflare 공식 개요](https://developers.cloudflare.com/ai-gateway/), [Flue 모델 연결](https://flueframework.com/docs/guide/models/).

Flue·Hermes·Agents API는 실행기 역할이 겹칩니다. 먼저 가상 정상 주문·정보 누락·주문 후보 충돌 3건과 같은 읽기 도구로 각 실행 경로를 작게 확인해, 도구 호출·결과 계약·재시도/중단·지연·비용·실행 기록을 비교합니다. 그 결과로 주 실행기를 정하고 실제 역할이 있는 보조 경로만 함께 둡니다. 한 요청에 세 실행기를 연쇄 배치하는 것을 목표로 삼지 않습니다. 이 연결 실험에는 별도의 모델 접근과 자격 증명·호출 상한 확인이 필요하며, 이번 문서 수정으로 키 생성·과금·운영 배포를 실행하지 않습니다.

### 에이전트가 사용할 정보와 도구

각 도구는 판매자 범위, 입력 스키마, 최소 반환 필드, 근거 ID·자료 버전, 실패 상태를 계약으로 갖습니다. 처음부터 연결을 완료한 것처럼 표시하지 않고 아래 업무별 실제 읽기 검증을 수행합니다.

- **상품·옵션·별칭·재고**: 저장소 JSON을 실제 읽는 검색·상세 도구를 먼저 만들고 이후 지정된 상품 시트나 DB 어댑터를 연결합니다. 재고 변경은 분석 도구에서 제공하지 않습니다.
- **배송·할인·교환 정책과 FAQ**: 승인된 정책 JSON·문서만 검색·읽고 출처와 버전을 반환합니다. 프로젝트 기획서와 DM 말투 예시는 판매 정책 승인 근거로 쓰지 않습니다.
- **주문·발송 기록**: 고객 아이디·이름 검색과 후보 상세 조회를 제공하고 모호한 후보를 숨기지 않습니다. 모델에는 조회와 승인 명령을 분리해 노출합니다.
- **판매 일정**: 공구 마감은 상품 자료의 명시된 시각으로 확인합니다. 출고·휴무 일정은 지정된 업무 캘린더나 일정 파일이 있을 때 읽기 도구로 연결하며, 일정이 없으면 추정하지 않습니다. 서버 시간·시간대·조회 구간도 기록합니다.
- **문서·파일**: 승인된 문서 ID나 허용 디렉터리 안의 파일을 읽는 도구를 제공합니다. 모델이 임의 로컬 경로·비밀 설정·평가 정답을 열지 못하게 하고 경로 이탈·심볼릭 링크 우회를 검사합니다.
- **외부 API·MCP**: 자료 서비스의 공식 API나 MCP를 우선 사용합니다. 주소 API는 기존의 가상 주소 외부 전송 금지와 원문 보존 조건을 유지하고, 택배 API 송장 발급은 기존 제외 범위를 유지합니다. 쓰기 도구는 판매자 승인 경계가 구현된 뒤 별도로 연결합니다.

Codex에서 연결된 Drive·Calendar·MCP가 있다는 것만으로 배포 앱에 같은 연결이나 자격 증명이 생기는 것은 아닙니다. 서비스가 사용할 자료 ID·인증·권한 범위를 따로 구성하고 실제 읽기까지 검증합니다. 실제 판매자의 문서·시트·업무 캘린더는 아직 지정되지 않았으므로 현재는 연결 대상으로 확정하지 않습니다.

### 구현 순서와 산출물

1. **최소 백엔드 실행 기반과 계약**: TypeScript strict·Node LTS·npm을 추천합니다. `src/domain`에는 입출력 스키마와 계산·검증 규칙, `src/agent`에는 모델과 도구를 연결하는 실행 흐름, `src/adapters`에는 자료·모델 연결, `src/cli`에는 실행·평가 진입점, `src/http`에는 채팅 수신 API를 둡니다. 필요한 린트·타입검사·단위 테스트만 함께 구성합니다. HTTP 서버 구성은 첫 단계에서 선택하되 화면 프레임워크·컴포넌트·브라우저 테스트는 아직 설치하지 않습니다. 런타임·패키지 버전과 잠금 파일은 실제 설치·검증 후 고정합니다.
2. **자료 조회 도구와 코드 검증**: 기존 JSON의 상품·별칭·정책·주문 조회를 읽기 전용 도구로 제공합니다. 도구 인자는 실행 시 검사하고 판매자 범위를 서버에서 정합니다. 입력 기준 시각과 자료 버전을 주입하며, 조회 자료는 모델 판단의 근거로만 사용합니다. 가격·할인·배송비 계산, 수량·옵션·누락 검사는 코드가 담당합니다. 분석 경로에 주문·재고 쓰기 도구를 연결하지 않습니다.
3. **지정 기술의 연결 검증과 단건 에이전트**: 위 실행기·Jev·게이트웨이 연결을 검증하고 주 실행기를 정합니다. 입력 검증 → 문의 분류 → 필요한 도구 조회 → 구조화 추출 → 코드 검증·계산 → 답장 초안 → 근거 대조를 연결합니다. 모델이 자료 조회 도구를 사용할 수 있게 하되 호출 가능한 도구와 쓰기 금지는 코드로 제한합니다. 각 책임을 별도 에이전트나 별도 모델 호출로 강제하지 않습니다. 공급자·모델·SDK는 지정 기술 축 안에서 구조화 출력·도구 호출·실행 기록·비용·호환성을 비교해 첫 실제 호출 전에 결정합니다. API 키는 서버 환경에서만 읽고, 호출/토큰·도구 실행·재시도·시간·평가 비용 상한도 실행 전에 설정합니다. 이 작업은 현재 키 생성이나 과금을 수행하지 않습니다.
4. **채팅 API·CLI 실제 실행과 평가**: `POST /api/chat`으로 고객 아이디·대화 원문을 받아 실제 에이전트를 호출하고 `io-spec.md` 형식의 JSON 결과를 반환합니다. CLI도 같은 코어를 사용합니다. HTTP 요청 검증·오류 응답·크기/시간 제한을 서버 경계에서 처리하고 판매자·기준 시각·자료 버전은 서버가 정합니다. 현재 API는 동기식으로 처리하며 서버가 SQLite의 해당 방 이력을 읽습니다. 스트리밍은 후속입니다. 구체적인 HTTP 계약은 [입출력 명세](io-spec.md)의 1.1절을 따릅니다. 먼저 정상 주문·정보 누락·상품 모호·주문 후보 충돌·입금 주장·DM 속 지시문 공격을 실제 모델로 실행합니다. 이후 가상 DM 40건을 평가하고 사례별 결과·오류·근거·지연·사용량과 비용을 기록합니다. 현재 소량 연결 검사는 통과했으나 아래 전체 사례·40건 평가는 아직 수행하지 않았습니다. 실제 비용을 얻지 못한 경우 추정값과 구분합니다. 모델 없는 단위 테스트와 실제 모델 평가는 명령·결과를 분리합니다.
5. **주문 백엔드와 승인 API 확장**: 읽기 기반 에이전트의 첫 검증 후 이미 구성한 SQLite 자료 저장소 위에 주문 명령용 스키마·마이그레이션을 구체화합니다. 승인자 문맥, 최신 가격·정책·재고·버전 재검사, 중복 명령과 동시성·원자성부터 검증합니다. 이후 후보 저장·조회·판매자 확정·수동 발송 명령과 로컬 API를 연결합니다. 모델에는 자동 확정 권한을 주지 않습니다. 이미 구성한 HTTP 서버에 주문 명령 경로를 추가하고 분석 API와 승인 명령의 권한을 분리합니다.

1~4가 첫 부트스트랩의 완료 범위이며 5는 다음 백엔드 단계입니다. DB 상세 설계와 거래 안전성 검사는 주문 쓰기 구현의 선행조건이지, 읽기 전용 에이전트 검증의 선행조건은 아닙니다.

### 첫 부트스트랩 완료 기준

- 새 설치에서 잠금 파일로 실행 환경을 재현하고 채팅 API와 CLI 양쪽으로 가상 DM을 처리할 수 있습니다. 정상 요청은 실제 에이전트 결과를 반환하고, 잘못된 입력은 모델 호출 전에 거절하며, 모델 실패·시간 초과는 정상 결과와 구분합니다. HTTP 통합 검사도 완료 조건에 포함합니다. 환경 예시에는 비밀 값이 없으며 로컬 설정과 실제 DM·주소·전화번호를 커밋하지 않습니다.
- 입력·모델 출력·도구 인자를 실행 시 검증합니다. 자료·모델·검증 실패는 `failed` 등 계약상의 오류로 반환하며 미검사를 통과로 표시하지 않습니다. 빈 아이디 등 입력 오류는 모델 호출 전에 거절합니다.
- DM-002를 실제 처리한 결과가 상품합 62,000원 − 할인 3,000원 + 배송비 3,000원 = 총 62,000원과 일치합니다. 모델이 제안한 금액을 정답으로 사용하지 않습니다. DM-003의 누락, DM-004·017의 상품 모호성, DM-009의 주문 후보 충돌을 임의로 채우거나 확정하지 않습니다.
- DM-014의 정책 무시 지시와 DM-018의 입금 주장이 정책 변경·주문 확정·재고 변경으로 이어지지 않습니다. 분석 전후 자료가 같고, 실제 호출 기록으로 도구 조회와 검증 단계가 실행됐는지 확인합니다. 기대값·해설·태그는 평가기만 읽고 에이전트 입력에 주지 않습니다.
- 가상 40건의 분류·추출·누락·근거 오류를 정답과 독립 대조해 결과와 미달 항목을 남깁니다. 금액 일치만으로 답변 전체의 사실성을 보장하지 않습니다. 승인 경계 위반·근거 없는 자동 확정 등 차단 실패가 있으면 완료로 보고하지 않습니다.
- 실제 과거 DM 50건의 분류 90%·초안 사용 가능 70%·근거 없는 정보 0건·추출 95%·누락 감지 100% 목표는 별도입니다. 가상 평가로 달성했다고 보고하지 않으며, 사람이 판단할 초안 적합성을 자동 평가만으로 확정하지 않습니다.
- 설치·빌드·린트·타입·테스트·단건 실행·가상 평가의 정확한 명령을 실제 구현 후 README에 기록합니다. CI는 비밀 키 없이 실행하는 코드·자료 검사를 기본으로 하고 실제 모델 평가는 명시적으로 실행·기록합니다. 현재 실행·검사 명령은 README와 backend.md에 기록했습니다.

### 후속 단계와 미룬 이유

- **웹 검토 화면·디자인·Playwright**: 실제 결과 계약과 오류 동작을 검증한 다음 그 결과를 표시합니다. 고정 예시 화면 제작을 에이전트 개발보다 앞세우지 않습니다. Next.js는 현 단계의 필수 선택에서 뺍니다.
- **주문 쓰기용 SQLite 확장**: 파일 SQLite를 기본으로 채택했습니다. 주문 승인 서비스 구현 전 트랜잭션·버전·멱등성·동시 확정 검증을 마칩니다. 샘플 재고는 기존 주문 반영 후 스냅샷이므로 seed 시 재차 차감하지 않습니다. 다중 서버 공유 저장이 필요해질 때 별도 DB를 재검토합니다.
- **여러 건 처리·택배 엑셀·주소 API·Sheets**: 단건 에이전트·주문 백엔드 다음에 연결합니다. 첫 MVP 범위에서 삭제하지 않으며 실제 양식·연동 조건을 먼저 확인합니다.
- **운영 인증·외부 배포·백업/복구**: 실제 자료·공개 서비스 사용 전에 갖춥니다. 개발용 고정 판매자 문맥을 운영 인증으로 쓰지 않습니다.

### 사용자 결정과 다음 행동

현재 필요한 방향은 서비스로 이어갈 기반, 백엔드·에이전트 우선, 지정 에이전트 기술과 자료·도구의 적극적인 연결로 정해졌습니다. 호스팅·택배사·화면 디자인을 지금 추가 질문하지 않습니다. 다음 구현의 출발점은 입력·출력 계약과 읽기 도구를 갖춘 백엔드 코어이며, 첫 완료 시연은 채팅 API 요청부터 실제 모델·도구 조회·검증·JSON 응답까지의 전체 흐름입니다. CLI는 같은 코어의 개발·평가 진입점입니다. 모델 호출 전에는 사용할 공급자·모델·자격 증명 경로·비용 상한을 구체화합니다.

### 마피아 MCP 적용 근거

기존 `plan` 절차를 유지하고 사용자 수정에 따라 우선순위·구현 경계·검증 방법의 세 지점을 각각 다시 검색했습니다. 관련 카드의 일반 판단만 적용하며 카드가 특정 스택이나 구현 순서를 정해 준 것으로 해석하지 않습니다.

- 「선행조건을 걸기 전에 누구에게 걸리는 조건인지 가리고, 독립된 작업은 병렬로 둔다」 (`k1d36022857`): DB 거래 검증은 주문 쓰기에 필요하며, 읽기 에이전트와 실제 모델 검증을 막는 조건으로 두지 않습니다. 화면은 사용자의 지시에 따라 미룹니다.
- 「같은 수작업이 반복되면 기능보다 자동 반영 장치를 먼저, 흔하고 단순한 구조로 만든다」 (`kf40af93477`): 피해야 할 결과와 검증 방법을 먼저 정하고 프로젝트 규모에 맞는 최소 실행·평가 환경을 둡니다.
- 「동작 확인을 사용자에게 넘기기 전에 브라우저 자동화로 직접 end-to-end 테스트한다」 (`k82f4ec7618`): 직접 실행 후 보고한다는 일반 원칙을 적용합니다. 지금 브라우저 화면을 새로 만들라는 뜻으로 해석하지 않고 CLI에서 모델·도구·검증까지 실행합니다.

사용자의 채팅 수신 API 추가에 따라 수신 경로를 첫 부트스트랩에 포함했습니다. 마피아 MCP에서 범위를 재검색했으며 「배포 후 동작 확인과 테스트 데이터 정리를 사용자에게 넘기지 않고 끝까지 직접 한다」 (`ka6807a6552`)의 직접 검증 원칙을 로컬 HTTP 요청부터 에이전트 응답까지 확인하는 기준에 적용합니다. 배포·DB·화면을 먼저 만들라는 의미로 적용하지 않습니다.

## 미정 사항과 결정 시점

- 실제 셀러·상품 정책·택배사 양식: 실제 업무 검증과 출력 어댑터 구현 전에 확인합니다. 가상 자료 작업은 진행할 수 있습니다.

- 실제 개인정보 보관·삭제·외부 전송·운영 인증: 실제 자료를 받거나 외부 배포하기 전에 확정합니다.
