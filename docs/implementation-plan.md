# 구현 순서와 결정 목록

상태: 제작 준비 초안. 이번 작업은 문서·가상 자료 작성이며 앱 구현은 포함하지 않습니다.

## 실행 순서

1. **입출력 계약 검토**: DM-002 정상 주문과 DM-003·009 예외를 따라 초안 저장·승인 흐름을 확정합니다. 완료 산출물은 수정된 명세와 UC-02 화면 시안입니다.
2. **스택과 실행 환경 구성**: 단일 앱·자료 어댑터·상태 저장 방식을 선택합니다. AC-09~11의 원자성을 먼저 확인하고 설치·실행·검증 명령을 문서화합니다.
3. **가상 자료 기반 단건 흐름**: 분류·추출·코드 검증·근거 초안과 검토 화면을 연결합니다. 관련 AC와 DM 40건을 실행해 결과를 남깁니다.
4. **주문·조회·확정·발송 기록**: 초안 저장과 확정을 분리하고 멱등성·동시성·실패 롤백을 검증합니다. UC-06의 수동 발송 등록·정정과 AC-18~21도 함께 구현·검증합니다.
5. **일괄 처리·택배 내보내기**: 건별 실패·고객 격리를 검증하고 실제 양식 확보 후 출력 어댑터를 구현합니다.
6. **실제 자료·운영 검증**: 셀러 정책·사용 권한·보관 기준을 정하고 실제 DM 50건 평가와 1주 사용 검증을 진행합니다.

## 지금 유지하는 결정

- D-01: 첫 버전은 DM 수동 입력·직접 발송·수동 입금 확인. 근거는 원문 기획입니다.
- D-02: 분류·추출·초안을 분리하고 숫자·상태 변경은 코드로 검증합니다. 근거는 전달받은 피드백과 오류 비용입니다.
- D-03: 초기 제작 자료는 가상 JSON으로 제공합니다. 실제 판매 정책·개인정보로 오해하지 않도록 표시합니다.
- D-04: 문서별 책임을 나누되 오류·운영·결정 기록은 관련 문서에 합쳐 관리합니다. 근거는 마피아 MCP 검토와 초기 프로젝트 규모입니다.

## 미정 사항과 결정 시점

- 실제 셀러·상품 정책·택배사 양식: 실제 업무 검증과 출력 어댑터 구현 전에 확인합니다. 가상 자료 작업은 진행할 수 있습니다.
- 스택·모델·저장소·호스팅: 단건 구현 전에 결정합니다. 선택 기준은 구조화 추출, 승인 원자성, 검증 편의, 비용·지연입니다.
- 입력 길이·일괄 건수·재시도·비용 상한: 가상 실행 측정 후 정합니다. 근거 없는 숫자로 고정하지 않습니다.
- 실제 개인정보 보관·삭제·외부 전송·운영 인증: 실제 자료를 받거나 외부 배포하기 전에 확정합니다.
- 확정 후 취소·환불·주소 변경 절차: 실제 판매자 사용 전 정합니다. 자동 처리 기능은 제외합니다.

## 추가 문서가 필요한 시점

HTTP API가 생기면 실제 엔드포인트·인증·오류 계약을 입출력 명세에 보강합니다. 외부 공개·다인원·고가용성 요구가 생기면 권한 모델·배포/복구 절차·운영 목표를 확장합니다. 지금은 존재하지 않는 기술의 설치법이나 인프라 구성을 만들지 않습니다.
