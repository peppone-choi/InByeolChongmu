# 운영·보안·배포 준비

상태: 운영 전 체크 초안. 현재 서비스·운영 계정·배포·실제 고객 데이터는 없습니다.

## 데이터와 접근

- 가상 자료와 운영 자료를 분리합니다. 샘플 아이디·전화·주소·송장을 실제 발송이나 주소 조회에 사용하지 않습니다.
- 운영 전 실제 DM의 사용 권한, 수집 항목, 외부 모델·API 전송 범위, 접근 주체, 보관·삭제·백업 정책을 확정합니다. 특정 법정 보관기간을 임의로 정하지 않습니다.
- 판매자 1명이라도 외부에 공개하면 인증과 본인 자료 접근 제한이 필요합니다. 브라우저가 보낸 판매자 ID만으로 권한을 부여하지 않습니다.
- 실제 개인정보·비밀 키는 Git·일반 로그·오류 화면에 남기지 않습니다. 주소 조회에는 필요한 검색어만 전송하고 이름·연락처는 제외합니다.
- 엑셀 내보내기에서는 고객 입력의 수식 실행과 전화번호 앞자리 손실을 막습니다. 다운로드 파일의 보관·삭제 방식도 운영 전 정합니다.

## 관측과 장애 대응

요청 ID·자료 버전·분류 단계·검증 코드·소요 시간·비용을 기록하되 본문·주소·전화번호는 기본 로그에서 제외합니다. 승인 명령과 재고 변경은 민감값을 최소화한 감사 기록으로 추적합니다.

- 모델·상품 자료 장애: 정상 초안으로 표시하지 않고 건별 실패를 유지합니다.
- 주문 저장 장애: 확정 성공을 표시하지 않습니다. 명령 결과 조회로 성공 여부를 확인한 뒤 같은 키로 재시도합니다.
- 주소 API 장애: 원문 보존·미검증 표시 후 판매자 확인 흐름으로 넘깁니다.
- 양식 내보내기 실패: 성공·제외·실패를 구분하고 확정·발송 상태를 바꾸지 않습니다.

재시도 횟수·시간 제한·로그 보관기간·예산 경보·담당 연락 경로는 측정과 운영 조건을 확인한 뒤 정합니다. 자동 무한 재시도·실패 은폐는 허용하지 않습니다.

## 배포 전 완료 조건

1. 스택·환경 변수 이름·설치/실행/검증 명령과 예시 설정을 문서화합니다.
2. 자료 변경·승인·재고의 원자성, 권한, 오류·개인정보 누출을 검증합니다.
3. 실제 택배 양식과 내보내기 자료형을 확인하고 UC-01~05를 수행합니다.
4. 백업·복구·배포 롤백 방법을 확인합니다. 코드 롤백으로 이미 확정한 주문·재고를 자동 되돌리지 않습니다.
5. 데이터 삭제·보관, 실제 셀러 정책과 운영 책임자를 확정합니다.

확정 이후 취소·환불·주소 수정의 업무 절차는 미정입니다. 실제 판매자 사용 전 필수로 정하고, 모델이 자동 처리하지 않도록 유지합니다.
